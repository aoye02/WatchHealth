## 演示四步话术（袁志强口播，数字均为真实跑出来的）
1. **看板**："大家看，这是一位测试用户期末周前后的 14 天真实数据——这个人模型训练时没见过。四条线：心率、HRV、深睡、步数。注意最后两天 HRV 的断崖。"
2. **预测**："我点一下'生成明日预测'……系统给出明天压力 **8.5**，疲劳 7.6，推荐轻运动，今晚 23:30 前睡。这位同学当天真实自评就是 8.5——预测几乎完全命中。这个数字是 LSTM 基于过去 7 天数据回归出来的。"
3. **预警**："这边红色卡片——HRV 从个人基线 **46ms 掉到 24ms**，下降 **49%**，z 分数 -5.4。这是滑动窗口 z-score 触发的，相当于手表在说'兄弟你最近不对劲'。"
4. **AI 简报**："最后这段是人话版本。我们把预测结果喂给讯飞星火，生成温和的提醒而不是冷冰冰的数字。页面右下角会标注来源——星火实时生成，或本地模板兜底。"

## 答辩 Q&A（老师可能的追问 + 标准回答）
| 问题 | 回答 |
|---|---|
| 为什么用 LSTM 不用 Transformer？ | 数据量只有几百条样本，Transformer 参数多容易过拟合；LSTM 5.4 万参数更稳。数据上量后会升级 Transformer，架构已留好接口。 |
| 这真的准吗？ | MAE 0.73，在 1–10 分量表上误差不到 1 分，作"趋势提醒"足够；但绝不能作医疗诊断，Reflection 里已写明。 |
| 训练/测试怎么划分的？ | 留一用户法：5 人训练、1 人测试，检验对"没见过的人"的泛化——这正是真实使用场景。随机打乱划分会让相邻天数据同时进训练测试，等于泄题。 |
| 标准化有数据泄漏吗？ | 没有。mu/sigma 只用训练用户的数据拟合，测试用户只 transform。代码在 data_utils.py 的 fit_scaler。 |
| 为什么窗口选 7 天？ | 做过消融：14 天窗口 MAE 0.80 反而比 7 天的 0.73 差——更多历史引入了噪声。7 天也刚好覆盖一个完整星期周期。 |
| 疲劳指数怎么算的？ | 目前是与压力相关的简化估计（stress×0.9），是工程占位。真实做法是多头输出或多任务学习，已写进 P12 未来工作。 |
| 异常检测为什么用 z-score 不用 LSTM 重构误差？ | 数据量太小，重构器训练不稳；z-score 可解释、零训练成本、按个人基线自适应。重构误差法列入未来工作。 |
| HRV 是什么？ | 心率变异性，两次心跳间隔的波动程度。压力大、熬夜、生病时 HRV 会下降，是国际上公认的自主神经状态指标，Apple Watch、华为手表都在用。 |
| 数据是真的吗？ | 两路：WESAD 公开数据集 + 组员自采集。演示 pipeline 先用合成数据跑通，合成规则基于生理先验（压力大→HRV 降、深睡降、静息心率升），真实数据接入后同一套代码直接复用。 |
| 单变量 LSTM 为什么比 MLP 还差？ | 这正是我们的发现：HRV 个人基线差异大（有人 30ms 有人 80ms），只看 HRV 换个人就漂移；多变量互相校准才稳。这说明"多变量"不是堆料，是必要的。 |
| 压力标签怎么来的？ | 每晚自评 1–10 分。主观性是最大的局限，已写进 Reflection；未来可用 PSS 量表或皮质醇检测校准。 |
